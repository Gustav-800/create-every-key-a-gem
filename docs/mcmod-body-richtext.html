机械动力：字字珠玑（Create: Every Key a Gem）

Create: Aeronautics 无线红石打字机的客户端按键保护附属

一、模组简介

机械动力：字字珠玑是「机械动力：航空学」无线红石打字机的客户端辅助模组。

它解决的问题很简单：打字机激活后，按下绑定的按键应该只发送无线红石频率，而不应该打开其他模组的背包、地图、任务书或设置界面。

二、问题背景

无线红石打字机激活时会接管键盘。但 Simulated 只在 NeoForge 的按键事件分发末尾清理原版按键状态。此时：

  1. 原版已经把按键排入按键映射；
  2. 其他模组的按键监听器可能已经执行；
  3. 直接读取原始按键的模组完全不受清理影响。

因此，如果某个键同时是打字机键和其他模组的快捷键，按下后就会弹出那个模组的界面。打字机检测到屏幕被打开，会强制断开，正在进行的敲击随之中断。

三、模组功能

当打字机处于以下状态之一，并且没有打开任何界面时：

  1. 正在操作打字机，也就是激活状态；
  2. 手持打字机物品，给无线红石接收器绑定按键。

本模组会：

  1. 先把按键事件原样交给 Simulated 自己的打字机处理器，保证频率包、声音、按键记录和动画都正常；
  2. 在客户端键盘处理入口取消事件；
  3. 使这次按键不再进入原版按键映射、NeoForge 按键事件或其他模组的键盘处理。

因此打字时不会触发其他模组的键盘快捷键。

四、按键说明

  • 已绑定的打字机键：正常发送无线红石频率，不触发其他模组。
  • 未绑定的按键：被打字机接管，不触发原版或其他模组快捷键。
  • Esc：退出打字机，由打字机自身处理。
  • F2：保留截图。
  • F11：保留全屏切换。

鼠标快捷键不在处理范围内。

五、工作原理

模组通过 Mixin 在客户端键盘处理入口注入。对 Simulated 的处理类使用反射调用，因此：

  1. 编译时不依赖 Simulated 的 jar；
  2. 不打包、不重编译 Simulated 的任何代码；
  3. 如果将来 Simulated 修改了相关接口，模组会记录一条警告并回退到正常键盘行为，而不是让游戏崩溃。

模组不添加物品、方块、配方或网络包，也不修改服务端逻辑。

六、环境要求

  • Minecraft：1.21.1
  • NeoForge：21.1.228 或更高
  • Create: Aeronautics：1.3.2 或更高，内含 Simulated 1.3.2 或更高
  • Create / Sable：Create: Aeronautics 的前置模组
  • 安装侧：仅客户端

七、安装方法

  1. 安装 Minecraft 1.21.1 和 NeoForge 21.1.228 或更高版本；
  2. 安装 Create: Aeronautics 及其前置 Create、Sable；
  3. 把 create-every-key-a-gem-1.0.0.jar 放入整合包的 mods 文件夹；
  4. 完全退出并重启游戏。

服务器不需要安装此模组，它不会发送额外的网络包。

八、配置

1.0.0 没有配置文件，也没有按键设置。打字机激活时即接管全部键盘按键，Esc、F2、F11 为固定例外。

九、兼容性说明

  • 本模组适用于任何服务端，因为它只修改客户端输入处理。
  • 打字机的按键编辑界面是普通界面，本模组不接管该界面，JEI 等界面快捷键仍可正常使用。
  • 如果某个模组直接通过 GLFW 轮询物理按键，而不经过按键映射或 NeoForge 按键事件，该模组仍可能看到按键。绝大多数快捷键模组使用标准路径，已被覆盖。
  • 本模组与 Create、Create: Aeronautics、Simulated 官方无隶属关系。

十、常见问题

问：服务器需要装吗？
答：不需要，这是纯客户端模组。

问：会改变打字机本身的功能吗？
答：不会。按键仍会交给打字机处理器，模组只是阻止事件继续传给原版和其他模组。

问：为什么不做成可配置的按键白名单？
答：打字机激活时本来就设计为接管键盘。1.0.0 先保证按下什么都不会打断打字机；如果后续有明确需求，再考虑配置。

问：会支持其他版本吗？
答：1.0.0 面向 1.21.1 和 NeoForge。其他版本需要重新适配并测试。
